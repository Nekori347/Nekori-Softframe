# 信息架构、表达与命令

依据：批次009；内容完整与结构优先补充来自003。适用于跨项目产品UI，不绑定COMM Desktop等项目。

## 功能先归属，再决定入口

| 功能性质 | 默认归属 | 避免 |
| --- | --- | --- |
| 单对象编辑 | 对象、行内工具、详情 | 新增全局导航 |
| 选中对象批量操作 | 选择后的上下文区域 | 常驻无关按钮 |
| 筛选/排序 | 当前视图工具栏 | 另建页面 |
| 网格/列表等显示模式 | 同视图分段或图标切换 | 两个顶层导航 |
| 次级对象动作 | 更多/右键菜单 | 每张卡片塞满按钮 |
| 全局偏好 | 全局设置与必要就地入口 | 每页重复设置器 |
| 预设管理 | 管理界面 | 每处复制管理器 |
| 预设使用 | 对应输入附近 | 为使用而跳转管理页 |
| 进阶参数 | 相关参数下的折叠分支 | 永久一级导航 |
| 操作结果 | 状态变化与必要反馈 | 大段成功说明 |

区分Navigation（前往内容）、Action（执行）、Mode（模式）、Filter（范围）、State（状态）、Property（参数）、Detail（详情）。功能有名字不意味着需要页面。入口按对象就地→视图→上下文→全局考量，最终由语义与频率决定；高频动作不能全部藏起来。

执行AI可处理技术细节，不能擅增顶层导航、常驻区域或改产品信息架构。变更分级：L0复用既有入口；L1对象内增强；L2视图内增强；L3新增局部控件先检查承载；L4新导航由指导AI判断确认；L5整体结构先设计。局部开发或修复不能自动升级L4/L5。

## 导航形式不等于语义级别

“左侧竖列一级→顶部标签二级→分支节点三级”是常见形式，不是固定架构。画师工作台/多文档应用可由顶部工作区标签承载一级，侧栏归当前项目；按任务和对象决定，不能为凑三级新增入口。参见[窗口与层级](08-窗口与层级.md)。

## 图标与文案

| 场景 | 表达 |
| --- | --- |
| 紧凑工具栏、熟悉行内动作 | 图标，配Tooltip、键盘焦点、无障碍名称 |
| 顶层导航 | 图标＋短名，或已有稳定识别的文字标签 |
| 分类 | 前置选中竖线＋可选图标＋名称 |
| 分支 | 名称＋折线/几何状态符号 |
| 模式 | 分段图标或短标签 |
| 保存/发送/导出等执行 | 短动词或图文 |
| 危险/不可逆动作 | 明确文字，图标可辅助 |
| 参数 | 用参数控件直接表达 |
| 帮助 | Tooltip/Popover/按需帮助 |

同一动作使用稳定的名称和图标，不把同步/更新/刷新随意互换。图标含义不清时补短标签；不能为了“纯图标”牺牲理解。

正式业务面保留参数名、单位、必要状态、错误、影响范围和风险。帮助按需呈现；删除营销副标题、开发说明、演示提示、重复页面名和重复解释控件用途的段落。文案只提供用户尚不知道且完成当前任务需要的信息。

## 内容决定尺寸

顺序：内容语义→最低占用空间→内边距→控件尺寸→外部布局。视觉居中需考虑三角重心、字形、胶囊弧端，不是仅设置几何居中。

- 文字按钮按最长合理文案和侧边留白定最小宽度。
- 图标绘制范围小于命中范围，图文组合图标不可被挤压。
- 分段项先完整显示再决定等宽；数值预留负号、小数、位数、单位和微调。
- 色块设最小可见尺寸；标签耳朵容纳文字、图标、顶部选中线；元操作外圈间隙计入总尺寸。
- 空间不足先外围伸缩/换行，再调整组件间距或用已有紧凑变体。不能先裁字、压图标、压扁色块。
- 确有限宽的导航可省略＋完整提示；数值、颜色、关键状态、当前操作不能默截。考虑字体回退与多语言长度。

## 对话框命令顺序

**自绘业务对话框：取消在左，主要动作在右。** 三选项为取消→不保存→保存。同应用跨页面、功能及迭代保持一致。一个真正的视觉主动作，不把危险与普通动作都做成主按钮。

Windows原生系统对话框/文件选择器保持其原生顺序，不为套用此规则重绘。此处是本套规范的选择，并非声称Apple和Microsoft原生顺序统一。

## 风险与行为

风险看后果、可恢复性、范围、误触概率、意图清晰度。可靠Undo优先，不用“destructive就一定弹窗”代替判断。

| 情况 | 默认处理 |
| --- | --- |
| 模式/标签/普通参数 | 直接执行 |
| 改名、标签、常规编辑 | 直接执行并合理撤销 |
| 移至回收站 | 优先执行＋恢复/Undo |
| 永久删除 | 一次明确确认，说明不可恢复及对象范围 |
| 批量覆盖、大量重置 | 确认影响范围 |
| 更换全局软件标识 | 因全局影响确认，不标成危险删除 |
| 未保存关闭 | 保存/放弃/取消 |
| 远端删除、不可逆同步 | 明确远端范围和后果后确认 |

取消是不提交目标变更；返回是上级导航；关闭按该表面的保存策略；Undo回退已发生操作；Discard丢弃未保存更改；任务停止必须真能中断。没有中断能力不画假的取消按钮。

自绘Dialog相对Owner窗口定位/居中，菜单和Popover锚定触发处。标题写具体对象与动作，正文只补必要后果。通常两按钮，有三个真实结果才三按钮。危险不可逆操作不由Enter默认执行；普通确认Esc安全退出；模态不穿透；提交防重复，失败保留可恢复状态。成功反馈真实结果，不连弹成功框。

一次必要确认足够。只有极高风险且超出当前明确选择范围才考虑输入对象名等额外保护，禁止连续同义确认。

命令区、确认、Undo、任务控制职责统一管理；ActionButton、IconToolButton、DialogActionBar、ConfirmDialog、DestructiveAction、UndoFeedback、TaskControl是语义职责，不要求创建七个独立组件包。

## 轻量验收

功能能执行之外，检查入口层级、组件语义、状态复用、内容完整、文案必要性、既有动线。做一次结构检查即可，不要求对每条设计偏好构建自动化测试。
